## 四、分级逻辑

两级过滤架构：

1. **L1 关键词预筛**（毫秒级，零 LLM 成本）
   - 致命词（死亡/爆炸/火灾/查封/失联/跑路/重大事故）→ 直接红色，跳过 L2
   - 严重词（违约/诉讼/冻结/调查/停产/裁员/暂停上市/评级下调）→ 进入 L2
   - 关注词（下降/亏损/延期/处罚/警告/减持/辞职）→ 进入 L2
   - 关键词库路径：`backend/config/keywords.yaml`（可配置）

2. **L2 LLM 精细分级**（~2-5 秒，按需调用）
   - 输入：原始信号全文 + 企业上下文
   - 输出：`{ severity, category, title, detail, suggested_action }`
   - 分级标准（按对客户损失的影响）：
     - 🔴 红色：可能直接导致贷款损失（违约/查封/死亡）
     - 🟠 橙色：偿付能力显著恶化（评级下调/大额诉讼）
     - 🟡 黄色：需要关注但不紧急（经营下滑/小纠纷）
     - ⬜ 无关：误报（记录但不推送）

## 五、推送路由

| 级别 | 推送时机 | 推送渠道 | 推送对象 |
|------|---------|---------|---------|
| 🔴 红色 | 5分钟内 | 飞书 Bot @ + 加急消息 | 风控总监 + 业务负责人 + 客户经理 |
| 🟠 橙色 | 每日 18:00 | 飞书消息 | 风控专员 + 业务负责人 |
| 🟡 黄色 | 每日 18:00 | 飞书消息 | 风控专员 |
| ⬜ 无关 | 不推送 | 仅写日志 | — |

## 六、数据存储

```sql
CREATE TABLE warning_log (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    enterprise    TEXT NOT NULL,
    source        TEXT NOT NULL,
    severity      TEXT NOT NULL,
    category      TEXT,
    title         TEXT NOT NULL,
    detail        TEXT,
    suggested_action TEXT,
    status        TEXT DEFAULT 'new',
    acked_by      TEXT,
    acked_at      TIMESTAMP,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    raw_data      TEXT
);
```

## 七、前端

在现有 Vue 3 前端侧边栏增加"预警中心"tab：
- 预警列表（分页/筛选：企业/级别/状态/时间）
- 预警详情弹窗
- 确认/误报操作
- 统计面板（按企业/级别/状态）

API：
- `GET /api/warnings` — 列表
- `GET /api/warnings/{id}` — 详情
- `PUT /api/warnings/{id}/ack` — 确认
- `PUT /api/warnings/{id}/false` — 误报
- `GET /api/warnings/stats` — 统计

```env
WARNING_CRON_INTERVAL=300          # 采集间隔（秒）
WARNING_SOURCE_TIMEOUT=30          # 单源超时（秒）
WARNING_KEYWORDS_PATH=./backend/config/keywords.yaml
WARNING_RED_MAX_DELAY=300          # 红色最大延迟（秒）
WARNING_DAILY_PUSH_TIME=18:00     # 日汇总推送时间
WARNING_ENABLED_SOURCES=all       # 启用的数据源
```
